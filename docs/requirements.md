# Brave ドメイン別ダウンロード振り分け — 要件定義

## Context
とーやは Mac と Windows の両方で Brave を使っている。サイト（ドメイン）ごとにダウンロード先を自動で切り替えたい。
- **ホワイトリスト方式**：登録したドメインだけ振り分ける。それ以外は Brave 標準の設定（既定フォルダ／毎回確認）のまま一切触らない。
- 保存先には **外部ストレージ**（Googleドライブ・Dropbox・外付けSSD など、Finder/エクスプローラーにマウントされている場所）も指定できる。
- 設定画面・ポップアップは見た目と使いやすさを重視する。

### 技術的な前提（重要）
Brave（Chromium）の拡張機能は、**既定のダウンロードフォルダの中**にしか保存先を指定できない。
→ 外部ストレージへ保存するため、**拡張機能 ＋ 小さな補助アプリ（ヘルパー）** の2部構成にする（とーや承認済み）。

## 決定事項（ヒアリング結果）
| 項目 | 決定 |
|---|---|
| 外部ストレージ保存 | ヘルパーアプリ方式（DL完了後に指定フォルダへ移動） |
| Mac/Win の設定共有 | ルールは共通（JSON エクスポート/インポート）、保存先パスは OS 別に持つ |
| ドメイン一致 | サブドメインも含む（ルールごとに「完全一致のみ」に切替可） |
| 置き場所 | `~/Documents/01_Project/shimau/` |

## 1. 機能要件

### F1. ルール（ホワイトリスト）
- ルール = 「ドメイン」→「保存先」。
- ドメイン判定は **ダウンロードを開始したページのドメイン**（タブURL／referrer）を優先し、取れない場合はファイルURLのドメインで判定。
  - 理由：Google ドライブ等はファイル本体が `googleusercontent.com` など別ドメインから来るため。
- 複数ルールに一致したら **より具体的なドメイン**（例 `drive.google.com` > `google.com`）を優先。
- ルールごとに ON/OFF、サブドメイン含む/完全一致 を切替。
- **一致しないDLには一切介入しない**（Brave標準のまま）。

### F2. 保存先（プリセット）
- 保存先は名前付きで登録（例「大学資料（Drive）」「動画（SSD）」）し、ルールから参照する。
- 1つの保存先に **Mac 用パス／Windows 用パス** を持たせる。今の PC の OS 側だけ使う。
- フォルダはヘルパー経由の **OS 標準フォルダ選択ダイアログ** で選べる（手入力も可）。
- マウント中の場所を一覧表示して選びやすくする
  - Mac：`/Volumes/*`、`~/Library/CloudStorage/*`（Googleドライブ・Dropbox）
  - Windows：ドライブ文字（`G:\` など）、Dropbox フォルダ
- 種類を自動判別してアイコン表示（Googleドライブ／Dropbox／外付け／ローカル）。

### F3. 振り分け処理の流れ
1. DL開始 → ルール判定。不一致なら終了。
2. 一致 → いったん通常どおりダウンロードフォルダに保存（完了まで待つ）。
3. 完了 → ヘルパーに「このファイルをこの保存先へ移動」を依頼。
4. ヘルパーが移動（別ドライブならコピー→検証→元を削除）。
5. 成功：通知「〇〇 を『大学資料（Drive）』に保存しました」＋「フォルダを開く」ボタン。

### F4. 失敗時の安全策
- 保存先が見つからない（SSD 未接続・Drive 停止など）→ **ファイルはダウンロードフォルダに残す**＋通知で知らせる。ファイルは絶対に失わない。
- 同名ファイルがある → 上書きせず `ファイル名 (1).pdf` のように連番。
- ヘルパー未インストール／応答なし → 振り分けをスキップし、設定画面にインストール案内バナー。

### F5. ポップアップ（ツールバーのアイコン）
- 今開いているサイトのドメインと、ルールの有無を表示。
- ワンタップで「このサイトを振り分けに追加」→保存先を選ぶだけで登録完了。
- 登録済みならその場で ON/OFF・保存先変更。
- 最近の振り分け 5 件（ファイル名・保存先・時刻、クリックでフォルダを開く）。
- ヘルパーの接続状態（緑／赤のドット）。

### F6. 設定画面（オプションページ）
左サイドバー + 右コンテンツの構成：
- **ルール**：カード一覧（ファビコン・ドメイン・保存先チップ・ON/OFF）。検索、追加、編集、削除（削除は元に戻すトースト付き）。
- **保存先**：プリセット一覧。Mac/Win パス、接続状態（今アクセスできるか）を表示。
- **履歴**：振り分け結果の一覧（成功／失敗、理由）。直近 200 件。
- **バックアップ**：JSON エクスポート/インポート（Mac⇔Win でルールを共有）。
- **ヘルパー**：接続状態、バージョン、インストール手順へのリンク。

### F7. 対象範囲外（今回はやらない）
- ファイル種類（拡張子）別のルール、日付サブフォルダ自動作成 → 将来の拡張候補
- Chrome ウェブストア公開・自動更新
- 自動同期（Brave Sync は拡張の設定を同期しないため JSON で代替）

## 2. UI / デザイン要件
- 雰囲気：Brave / macOS 設定アプリ風の、落ち着いたミニマルデザイン。余白多め。
- カラー：ニュートラルグレー基調＋アクセント1色（オレンジ系、Brave に合わせる）。**ライト/ダーク自動切替**（OS に追従）。
- 文字：システムフォント（Mac：ヒラギノ／SF、Win：Yu Gothic UI／Segoe UI）。UI は日本語。
- 部品：角丸 12px カード、トグルスイッチ、保存先チップ（アイコン＋名前）、トースト通知、空状態のイラスト付き案内（「まだルールがありません」）。
- 操作感：200ms 程度のさりげないアニメーション、キーボード操作対応、ポップアップは幅 360px 前後で一画面完結。
- 実装前に設定画面・ポップアップのデザインモックを1枚作ってとーやに見せ、OK をもらってから実装する。

## 3. 非機能要件
- 対応：Brave 最新版（Mac：Apple Silicon/Intel、Windows 10/11 x64）。
- 拡張機能は「パッケージ化されていない拡張機能を読み込む」で導入（開発者モード）。拡張IDは固定（manifest に key を入れる）→ ヘルパー側の許可設定を両PCで共通化。
- ヘルパーは **常駐しない**（Brave が必要なときだけ起動）。ネット通信なし。
- セキュリティ：ヘルパーは「ダウンロードフォルダ内のファイル」を「登録済み保存先」へ移動する操作のみ受け付ける。それ以外のパスは拒否。
- インストールは各 OS で1コマンド（Mac：`install.sh`、Win：`install.ps1`）。アンインストールスクリプトも用意。

## 4. 構成・技術選定（案）
```
01_Project/shimau/
├── README.md              使い方・インストール手順
├── docs/requirements.md   この要件定義
├── extension/             Brave 拡張（Manifest V3, TypeScript 不使用の素の JS + CSS）
│   ├── manifest.json      downloads / storage / notifications / nativeMessaging / tabs
│   ├── background.js      ルール判定・DL監視・ヘルパー呼び出し
│   ├── popup/  options/   UI
│   └── lib/               ドメイン判定・ストレージ等の共通処理
└── helper/                ネイティブヘルパー（Go 製の単体実行ファイル）
    ├── main.go            Native Messaging（移動・フォルダ選択・ボリューム一覧・フォルダを開く）
    ├── install/mac/       install.sh, ホスト定義 JSON
    └── install/windows/   install.ps1（レジストリ登録）
```
- ヘルパーを Go にする理由：Python 等のインストール不要の単体ファイルになり、Raspberry Pi 上で Mac/Win 向けにまとめてビルドできる。
- 主な API：`chrome.downloads.onCreated / onChanged`、`chrome.runtime.connectNative`、`chrome.storage.local`。

### 実装時に要確認のリスク
- Windows 版 Brave がヘルパー定義を読むレジストリの場所（Brave 独自キーか Chrome のキーか）→ 両方に登録して回避。
- Mac で未署名ヘルパーが Gatekeeper にブロックされる → install.sh で隔離属性を外す。外付けドライブ/クラウドへのアクセス許可ダイアログが初回に出る可能性。
- Googleドライブ（ストリーミング）へのコピーは同期待ちで遅いことがある → 移動完了の判定はローカル書き込み完了で行う。
- Brave で「保存する前に保存先を毎回確認」が ON の場合、振り分け対象でもダイアログが出る → 対象ドメインはダイアログなしで保存するかを実装時に挙動確認。

## 6. 検証方法
- Pi 上：ドメイン判定ロジックの単体テスト、ヘルパーの移動処理テスト（Linux でビルド・実行）。
- Mac / Windows 実機（とーやに実施してもらう）：
  1. 未登録サイトでDL → Brave 標準フォルダに保存される
  2. 登録サイトでDL → ローカル／Googleドライブ／Dropbox／SSD に移動される
  3. SSD を外した状態でDL → ダウンロードフォルダに残り、通知が出る
  4. 同名ファイル → 連番で保存
  5. JSON を Mac で書き出し → Windows で読み込み → ルールが反映される
- Codex で拡張・ヘルパーのコードレビュー。
- 完了後、`00_cc/01_Log/01_Activity/` にログ、`02_Knowledge/02_Decison/` にヘルパー方式採用の判断を記録。
